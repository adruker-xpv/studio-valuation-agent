build 13.2.6: onboarding validated end to end (review -> memory -> hand-off -> reuse)

Onboarding now runs from extraction through review, company memory and the
generation hand-off. Proven on Opus Q1 2026. Next phase is quarterly workbook
generation (Phase 6).

What the build does
- Extraction runs in two passes, 8 stages in total
  (ONBOARDING EXTRACTION, then ONBOARDING RESUME).
- review_xlsx 13.2.6 builds the review workbook with 3 decision sheets.
  Unresolved decisions accept only Correct or Reject.
- The review reader checks the bundle fingerprint, snapshot match, allowed
  answers and correction types. Any invalid row refuses the whole review and
  nothing is written.
- memory.py creates or extends company memory: entries are only added, with a
  hash chain and a coherence check. Blank answers are kept as pending,
  conflicting answers are STOPPED, and confirmed answers are saved as
  assumptions for that period.
- The hand-off builder writes 6.generation_handoff/... with status
  ready / ready_with_unresolved.
- Repeat runs reconcile against memory by concept and report reused /
  pending / reopened / new. Confirmed items are not asked again.

Known issues (not fixed here; Phase 6 entry items)
- Memory is attached at stage 6 instead of before stage 1, so stage 3 had to
  be revised after stage 8.
- A proposal can be dropped as 'unclear' without being flagged
  (13 proposals in r6 -> 12 in r7).
- Uploads are improvised: base64 printing, memory retyped from context,
  checkpoint uploads deferred.
- Harness mechanics still show in user-facing replies.
